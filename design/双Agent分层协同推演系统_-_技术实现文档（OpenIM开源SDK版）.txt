# 整体技术选型原则

## 核心选型逻辑

1. 基础设施全部采用开源SDK，无闭源依赖、可私有化部署、数据完全自主可控；

2. 通信层与业务层彻底解耦，IM仅做消息通知载体，核心业务状态、任务、断点、资产全部自研托管；

3. 适配AI辅助开发：分层清晰、接口统一、薄封装、无黑盒逻辑，AI可高效迭代维护；

4. 轻重能力分离：实时对话走轻量LLM流式链路，复杂多步骤推演走本地重度Agent异步链路；

5. 双通路交互兼容：支持人工面板手动操作、自然语言AI自动操作两套交互体系。

## 完整技术栈清单

### 客户端（Flutter 全端统一）

- IM通信底座：**OpenIM Flutter 开源SDK**（私有化自托管）

- 流式交互：自研SSE长连接客户端（独立于IM通道）

- UI架构：自定义原生组件（聊天面板、任务看板、动态表单渲染器）

- 本地存储：Hive（消息缓存、任务状态本地快照）

- 网络层：Dio 统一封装（接口、重试、超时、拦截器）

### 服务端架构（全自研）

- 中转调度核心服务（业务唯一状态源）

- 表层轻量LLM会话服务（SSE流式、记忆抽取、FunctionCall）

- Webhook事件网关（接收重度Agent回调事件）

- 结构化记忆资产存储服务

### 底层执行层

- 本地私有化重度Agent（复杂推演、多工具调用、断点挂起续跑）

- 开源无依赖，可随时替换任意Agent底座

## 架构核心设计准则

### OpenIM 只负责基础通信，不承载任何业务状态

- **承载范围：**双人文本对话、图片/文件附件、在线状态、离线消息、房间通知

- **严禁：**存储表单Schema、任务数据、断点状态、记忆资产

- **业务通知范式：**IM仅传递task\_id/breakpoint\_id轻量信号，完整数据由客户端主动拉取

### 双通信通道物理隔离（关键技术设计）

- 人类对话、系统轻通知 → OpenIM Socket 通道

- 表层LLM实时流式输出 → 独立SSE长连接通道

- 任务表单、断点交互、状态更新 → HTTP 接口通道

彻底解决流式卡顿、消息时序混乱、大JSON污染IM链路问题。

### 双Agent严格分层（价值与底座分离）

- **表层Agent：**产品核心资产，承载人机共识、对话治理、记忆沉淀、交互逻辑

- **重度Agent：**可替换算力底座，仅负责执行复杂任务，无业务资产沉淀

# OpenIM SDK 技术适配方案（核心落地规范）

## OpenIM 能力复用范围（完全覆盖需求）

基于开源 OpenIM Flutter SDK，复用全部原生成熟能力：

1. 会话能力：双人私有房间、专属会话隔离、多端同步

2. 消息能力：文本消息、图片消息、任意文件附件、消息撤回、已读回执

3. 自定义事件：自定义扩展消息（承载业务轻通知）

4. 基础能力：离线消息、在线状态、消息本地缓存、重连容错、私有化部署

## 自研 ImBridge 统一抽象层（AI开发专属防护层）

为适配AI辅助开发、实现IM底座可插拔，**强制封装统一抽象接口**，业务层永不直接调用OpenIM原生API。

### 抽象层核心接口定义

```dart
abstract class ImBridge {
  // 基础消息能力
  Future<void> sendRoomText(String roomId, String content);
  Future<void> sendRoomImage(String roomId, File imageFile);
  Future<void> sendRoomFile(String roomId, File file);

  // 业务事件通知（核心）
  Future<void> sendBusinessNotify(String roomId, Map<String, dynamic> event);

  // 事件监听
  Stream<BusinessNotifyModel> listenBusinessNotify();
  Stream<MessageModel> listenNewMessage();
}
```

- 所有OpenIM原生调用，仅在OpenIMBridgeImpl内部实现

- 后续如需切换Matrix等其他IM底座，仅需新增实现类，上层业务零改动

- AI迭代开发仅操作抽象接口，杜绝底层SDK耦合bug

## OpenIM 自定义消息规范（严格约束）

1. **禁止传输大体积JSON：**表单Schema、任务详情、断点描述绝不放入IM消息

2. 业务通知固定载荷格式（轻量、统一、可解析）

```json
{
  "eventType": "human_breakpoint",
  "taskId": "t-xxx",
  "breakpointId": "bp-xxx",
  "roomId": "room-xxx"
}
```

客户端收到通知后，**主动HTTP拉取完整业务数据**，保证状态源唯一。

# 双Agent核心业务技术实现

## 表层轻量Agent 核心能力实现

### SSE流式对话

- 独立长连接，不占用IM通道，实现逐字打字机流畅效果

- 对话结束后，完整应答落地存入OpenIM消息列表，用于历史回溯

- 支持主持人静默权限控制，精细化管控Agent响应规则

### 两大核心Function Call工具（自研核心）

1. **submit\_heavy\_task（任务下发工具）**

    - 自动汇总房间对话历史、业务约束、共识条件、交付要求

    - 封装标准化任务包，通过Webhook异步下发至本地重度Agent

    - 自动绑定roomId、taskId，实现任务与房间强隔离

2. **fill\_breakpoint\_form（AI自动填表工具）**

    - 解析用户自然语言对话，匹配当前房间待处理断点

    - 对照服务端返回的Form Schema，自动映射结构化表单数据

    - 自动校验必填项、枚举合法性，成功/失败双向反馈

    - 溯源标记提交来源：chat\_agent（AI自动）/panel\_human（手动）

## 重度Agent 交互技术规范

### 双向Webhook通信协议（标准化、可对接任意Agent）

1. **任务下发协议（调度服务 → 重度Agent）**携带完整对话上下文、业务约束、交付标准，杜绝执行偏差

2. **事件回调协议（重度Agent → 调度服务）**支持三类核心事件：

    - `human_breakpoint`：人工决策断点（携带完整表单Schema）

    - `task_finish`：任务执行完成（结果、摘要、附件）

    - `task_error`：任务执行异常（错误信息、失败原因）

### 断点挂起与续跑机制

- 重度Agent触发断点后，**自动挂起执行上下文、暂停推演**

- 等待调度服务回传结构化表单数据，恢复原有任务链路继续执行

- 支持任务取消、超时终止、异常重试机制

# HITL人机协同双通路技术实现（产品核心特色）

## 通路一：任务面板手动填表（基础通路）

1. 重度Agent触发断点 → Webhook回调调度服务存储表单数据

2. 调度服务通过OpenIM推送轻量通知至客户端

3. 客户端任务Tab红点提醒，用户切换面板

4. 前端根据标准化Form Schema**动态渲染原生表单**（单选/多选/输入框/备注）

5. 手动提交表单数据 → HTTP回传调度服务 → 下发重度Agent续跑

6. 全流程日志留痕，纳入结构化记忆资产

## 通路二：对话AI自动填表（智能通路）

1. 断点生成、红点提醒（同通路一）

2. 用户无需打开面板，直接在聊天框自然语言表达决策

3. 表层Agent识别当前房间活跃断点，触发fill\_breakpoint\_form工具

4. LLM语义解析自然语言，自动适配表单结构生成合法数据

5. 自动提交并在聊天框返回确认结果，全程无人工操作

6. 解析模糊/参数缺失时，自动降级提示用户前往面板手动填写

## 动态表单渲染核心技术

- 前端自研**通用Schema表单渲染器**（无第三方依赖）

- 一套代码适配全部断点表单，后端下发Schema，前端自动渲染UI

- 支持字段校验、必填判断、枚举限制、备注扩展、状态回显

# 风险规避与架构容错设计

1. **IM过载容错：**大体积业务数据绝不走IM，避免消息阻塞、超时、丢失

2. **状态唯一容错：**所有业务状态以调度服务为准，客户端、IM仅做展示

3. **AI填表容错：**语义模糊自动降级，杜绝错误自动提交

4. **链路隔离容错：**聊天流、任务流、流式流三通道独立，互不干扰

5. **可替换容错：**IM、重度Agent均为可插拔组件，不绑定单一底座
