# 协同推演陪跑系统 \- 产品需求文档（PRD）

**版本：**V0\.1（MVP版）　**定位：**面向咨询师\+行业专家双人协同，先对齐共识、再异步下发重型推演任务；支持重度Agent中途抛出结构化表单断点，支持人工面板填写与对话AI自动填表两条答复通路。

**核心架构：**表层轻量交互Agent（核心资产层） \+ 底层重度执行Agent（可替换算力底座）。

# 文档说明

## 产品目标

1. 搭建双人协同对话空间，咨询师（主持人）\+行业专家实时沟通、对齐需求、沉淀共识，形成可追溯、可版本化、可迁移的结构化咨询记忆资产（本产品核心壁垒）。

2. 将「共识对齐对话」与「重型多步骤Agent推演」解耦：前台对话流畅不阻塞，复杂长周期任务交给本地托管的重度Agent异步执行。

3. 支持重度Agent在推演中途触发人工断点（HITL）：抛出结构化表单Schema，渲染到独立任务看板；双答复通路并存——

    - **通路A（直接操作）：**用户打开任务看板，手动填写表单提交；

    - **通路B（对话驱动）：**用户在聊天框自然语言表达选择/意见，表层轻量Agent调用工具，自动识别、填充对应断点表单并提交。

4. 完整保留任务状态追踪、任务取消、断点溯源、记忆抽取归档能力。

## 范围（MVP包含 / 暂不包含）

### MVP包含

- Flutter客户端：双人聊天面板 \+ 独立任务看板（红点通知、动态表单渲染）

- 表层轻量LLM会话服务：流式对话、主持人权限、角色识别、对话存储、结构化记忆抽取

- 中转调度服务：房间会话管理、任务队列、task\_id/breakpoint\_id状态管理、Webhook事件收发

- 重度Agent对接：任务下发Webhook、断点回调Webhook、任务恢复/取消接口

- 表层Agent Function：fill\_breakpoint\_form（对话识别，自动填充并提交断点表单）

- 资产层：对话记录、断点选择记录、结构化记忆快照、版本留存

### MVP暂不包含

- 多房间多人并发权限精细化管理、组织租户体系

- 复杂文件在线预览、大文件内置编辑器

- 断点的审批流、多级复核

- 重度Agent原生自运维、自动重试、资源弹性调度（由重度Agent侧自行保障）

# 整体架构与数据流

## 架构分层

系统分为五层，客户端、调度、表层Agent、Webhook通信层、重度Agent各司其职，通信层与业务层彻底解耦。

## 双答复通路（重点）

同一个断点表单，两条提交路径，最终写入同一任务状态，重度Agent无感知差异；所有断点选择记录统一存入资产日志，进入结构化记忆抽取流程用于溯源。

# 核心功能模块详细需求

## 模块1：双人协同对话面板（表层轻量Agent）

1. 流式SSE对话，逐字输出，低延迟；

2. 角色身份识别：区分主持人/专家；支持主持人开关【Agent静默模式】（专家发言表层不响应，仅主持人发言触发）；

3. 对话全量持久化，每条消息携带发送人、时间戳；

4. 内置记忆抽取能力：定时/主动触发，从对话中提取约束、假设、共识、风险，生成结构化记忆资产，支持版本快照；

5. 内置两个核心Function Call（给表层LLM调用）——

    - **submit\_heavy\_task：**把当前房间对齐后的共识打包成结构化任务包，下发给重度Agent；入参：room\_id、summary、constraints、discussion\_history、deliver\_requirement；

    - **fill\_breakpoint\_form：**对话驱动填表工具。入参：room\_id、breakpoint\_id、user\_statement。工具逻辑：校验待处理断点 → 读取form\_schema → LLM映射为合法form\_data → 校验必填项与枚举 → 提交恢复接口 → 聊天框输出确认 → 写入资产日志；模糊无法匹配时返回失败，提示前往看板手动填写。

## 模块2：任务看板模块（独立视图）

看板是结构化事件的载体，与自然语言对话流隔离。

1. 看板列表：按房间隔离，展示全部任务，状态标签：排队中 / 运行中 / 待人工确认（红点） / 已完成 / 已失败 / 已取消；

2. 任务卡片基础信息：task\_id、任务摘要、创建时间、当前状态；

3. 待人工确认卡片：根据后端下发的form\_schema动态渲染表单组件，支持radio、checkbox、数字输入、文本框、备注域，自带提交/取消按钮；

4. 通知机制：新增human\_breakpoint事件时，客户端红点角标推送（聊天面板不强制插消息，遵循咨询节奏）；

5. 任务详情：查看重度Agent返回的结果摘要、完整结果、附件、执行日志；

6. 操作权限：主持人可取消任意任务；专家仅可填写自己可见的断点表单。

### 事件3：断点答复报文（统一格式）

```json
{
  "task_id": "t-20261101-001",
  "breakpoint_id": "bp-001",
  "form_data": {
    "scenario": "bear",
    "note": "优先评估下行风险，符合本次尽调要求"
  },
  "submit_source": "chat_agent"
}
```

submit\_source枚举：panel\_human（手动看板提交）/ chat\_agent（表层Agent对话识别提交），用于资产日志溯源。

### 配套事件

- `task_finish`：任务完成，携带摘要、结果、附件；摘要推送聊天框，完整结果放看板；

- `task_error`：任务异常，报错信息写入看板；

- `task_cancel`：取消任务指令，发送至cancel\_endpoint。

## 模块4：资产与记忆模块（核心壁垒）

1. **存储内容：**双人原始对话记录；任务生命周期日志、断点表单、答复内容、submit\_source来源标记；表层LLM抽取的结构化记忆（约束、假设、共识、验收标准、风险）；

2. **能力：**记忆快照、版本管理、导出、迁移到外部Agent；

3. **边界：**重度Agent内部推理草稿、中间临时日志不属于本产品资产，仅作为附件归档，不进入结构化记忆主体。

# 核心业务流程（两条断点答复路径）

## 流程A：看板手动填写（基础流程）

1. 咨询师\+专家在聊天面板对齐需求，表层Agent辅助澄清；

2. 主持人确认共识，调用submit\_heavy\_task下发任务给重度Agent；

3. 重度Agent开始推演，中途触发人工断点，推送human\_breakpoint Webhook；

4. 调度服务保存断点，Flutter任务看板红点提醒，渲染表单；

5. 用户切换到任务看板，手动选择、填写表单，提交form\_data；

6. 调度转发答复到重度Agent resume接口；

7. 重度Agent恢复执行，直到完成/再次断点；

8. 结果回传，写入资产日志，抽取记忆。

## 流程B：聊天对话驱动，表层Agent自动填表（新增流程）

1. 1\~4同流程A；看板出现红点断点（但用户不去看板）；

2. 用户直接在聊天框说：“我们选保守情景，备注优先控制下行风险”；

3. 消息送入表层轻量Agent；

4. 表层Agent识别当前存在待确认断点，调用fill\_breakpoint\_form工具；

5. 调度读取form\_schema，LLM解析自然语言映射为合法form\_data，校验合法性；

6. 自动提交form\_data给重度Agent；

7. 表层Agent在聊天框输出确认消息；

8. 日志标记submit\_source = chat\_agent；

9. 重度Agent继续推演。

**异常分支：**自然语言模糊，无法匹配schema → function返回失败，表层Agent回复“请前往任务看板手动填写表单”。

# 交互原型说明（Flutter端）

1. 页面布局：Tab切换（Tab1协同聊天面板 / Tab2任务看板面板）；

2. 红点提示：Tab2标签出现红点代表有待确认断点；聊天流不自动插入表单，保持对话干净；

3. 表层Agent填表成功后，聊天内生成一条确认消息作为过程留痕；

4. 表单渲染通用组件：一套通用渲染器，接收form\_schema自动渲染控件，无需为每个表单单独开发UI。

# 非功能需求

1. 表层对话SSE流式，token延迟控制在2s内；

2. Webhook事件重试机制：调度侧失败重试3次，超时标记失败；

3. 状态一致性：同一task\_id、breakpoint\_id保证幂等，避免重复提交；

4. 数据隔离：房间之间会话、任务、断点完全隔离；

5. 可替换性：重度Agent通过标准化Webhook协议对接，后续可替换底层执行引擎，表层、看板、记忆资产层完全不动。

# MVP上线验收标准

1. 双人进入房间，表层Agent流式对话、主持人静默开关正常；

2. 可以提交任务包，重度Agent正常接收并启动推演；

3. 重度Agent抛出human\_breakpoint，看板红点、动态表单渲染正常；

4. 通路A：看板手动填写提交，重度Agent接收答复继续执行；

5. 通路B：聊天自然语言输入，表层Agent调用fill\_breakpoint\_form自动填表提交，成功/失败分支正常；

6. 任务完成、任务取消、异常事件正常回调；

7. 所有对话、断点选择记录入库，可生成结构化记忆快照。
